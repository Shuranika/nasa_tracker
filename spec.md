# Спецификация: NASA Asteroid Tracker

## Цель

Настольное приложение показывает астероиды, сближающиеся с Землёй в выбранную дату, используя NASA Near Earth Object Web Service (NeoWs). Пользователь может просматривать результат из сети или ранее сохранённого локального кэша.

## Пользовательский интерфейс

- Одно главное окно с заголовком `NASA Asteroid Tracker`.
- Поле ввода даты с форматом-подсказкой `ГГГГ-ММ-ДД` и предзаполненной текущей локальной датой.
- Кнопка `Загрузить`.
- Область состояния: ожидание, загрузка, ошибка/предупреждение и источник данных (`NASA API` или локальный кэш).
- Таблица или прокручиваемый список результатов. Для каждого астероида показывать:
  - название;
  - диаметр (минимум и максимум, км);
  - скорость относительно Земли (км/с);
  - расстояние пролёта (км);
  - признак потенциальной опасности;
  - дату и время сближения (UTC), если NASA вернуло это значение.
- Пустой результат для корректной даты показывается как успешное состояние «Астероиды не найдены», а не как ошибка.
- Длинные значения и большие списки не должны ломать разметку окна; список должен прокручиваться.

## Поведение загрузки

1. По нажатию `Загрузить` приложение проверяет дату и не начинает HTTP-запрос при ошибке валидации.
2. Для даты `ГГГГ-ММ-ДД` выполняется запрос к NASA NeoWs Feed API с одинаковыми `start_date` и `end_date`, например:
   `GET https://api.nasa.gov/neo/rest/v1/feed?start_date=2026-10-12&end_date=2026-10-12&api_key=...`
3. HTTP-вызов выполняется асинхронно относительно GUI: окно должно оставаться отзывчивым.
4. При успешном ответе приложение декодирует данные, показывает результаты и обновляет кэш для выбранной даты.
5. Повторный запрос для даты может обращаться к сети; при сетевой ошибке используется кэш именно этой даты, если он есть. UI явно сообщает, что показаны кэшированные данные.
6. Если запрос завершился ошибкой и кэша нет, UI показывает понятную ошибку и сохраняет введённую дату. Нельзя выдавать пустой список за успешный ответ.
7. Ошибка чтения/записи кэша не должна скрывать успешный ответ API. Результаты API показываются, а проблема кэширования сообщается отдельно.
8. Для `DEMO_KEY` показывается уведомление, что ключ имеет ограниченные квоты. Ключ не отображается в UI и логах.

## Валидация даты

- Принимается только полная календарная дата ISO-формата `YYYY-MM-DD` (в UI подпись `ГГГГ-ММ-ДД`).
- Отклоняются пустая строка, неверные разделители, лишние символы, неполные даты и невозможные даты, например `2025-02-31` и `2025-13-01`.
- Текст ошибки должен объяснять требуемый формат и не очищать пользовательский ввод.

## API и данные

- Используется NASA NeoWs Feed endpoint.
- Модель ответа учитывает `near_earth_objects`, группу объектов по дате, `estimated_diameter.kilometers`, `close_approach_data`, `relative_velocity.kilometers_per_second`, `miss_distance.kilometers` и `is_potentially_hazardous_asteroid`.
- Недостающие необязательные значения отображаются как `—`; ошибка декодирования обязательной структуры отображается явно.
- Сетевые таймауты и неуспешные HTTP-статусы должны преобразовываться в информативные ошибки.

## Локальный кэш

- Кэш — JSON-файл в системной директории данных приложения (например, `NASA Asteroid Tracker/cache.json`).
- Запись организована по ISO-дате; результат для одной даты не затирает данные других дат.
- После успешного ответа API соответствующая запись сохраняется на диск. Запись должна быть защищена от частично записанного файла (временный файл с последующей заменой).
- Повреждённый или недоступный кэш не должен аварийно завершать приложение; UI сообщает о проблеме и продолжает сетевой сценарий.
- Формат кэша версионируется или читается так, чтобы ошибки несовместимого содержимого обрабатывались явно.

## Нефункциональные требования

- Поддерживаемые операции не блокируют основной поток GUI.
- Секреты не коммитятся. `NASA_API_KEY` задаётся через переменную окружения; при её отсутствии применяется `DEMO_KEY`.
- Базовые проверки выполняются командами `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings` и `cargo test`.
- Сетевые, календарные и файловые зависимости тестов подменяются; обычный запуск тестов не требует интернета.

## Критерии приёмки

1. Приложение запускается и показывает поле даты, кнопку и список/таблицу.
2. Корректная дата приводит к отображению данных NeoWs; поля форматируются с единицами измерения.
3. Невозможная дата отклоняется до сетевого запроса и сопровождается понятной ошибкой.
4. При сетевой ошибке отображается кэш для той же даты с маркировкой; без кэша отображается ошибка.
5. Успешный сетевой результат обновляет JSON-кэш в директории данных приложения.
6. Отказ или повреждение кэша не приводит к ложному сообщению об успешном кэшировании или к падению приложения.
7. Форматирование, clippy и автоматические тесты проходят.
