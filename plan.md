# План реализации

## Структура модулей

- `src/main.rs` — запуск `eframe`, инициализация приложения и настроек.
- `src/app.rs` — состояние и представление `egui`: дата, кнопка, состояния загрузки/ошибки, таблица результатов.
- `src/models.rs` — типы предметной области для астероида и сериализуемая модель кэша.
- `src/nasa/` — сетевой клиент NASA NeoWs и типы/преобразование JSON-ответа:
  - `client.rs` — URL, ключ из окружения, асинхронный запрос, таймауты и HTTP-ошибки;
  - `response.rs` — модели ответа и преобразование полей API в модели UI.
- `src/cache.rs` — путь в системной директории данных, чтение/запись JSON по дате и атомарное обновление.
- `src/date.rs` — разбор и проверка ISO-даты.
- `src/error.rs` (если проекту нужен единый тип ошибки) — ошибки сети, API, даты и файлового кэша с сохранением источника.

## Поток данных

1. UI получает введённую строку даты и вызывает валидатор.
2. При валидной дате UI запускает операцию загрузки вне блокирующего цикла отрисовки.
3. NASA-клиент возвращает типизированный ответ; парсер преобразует его в модели предметной области.
4. Успешные данные передаются UI независимо от результата последующей записи в кэш.
5. При сетевой ошибке сервис пытается прочитать сохранённый результат для той же даты. Возвращаемое состояние различает онлайн-данные и кэш.
6. UI обновляет статус и строки таблицы, сохраняя различие между пустым успешным результатом и ошибкой.

## Зависимости и границы

- Основные библиотеки: `eframe`, `egui` (обычно через `eframe`), `reqwest` с поддержкой TLS и async runtime, `serde`, `serde_json`.
- Добавлять только необходимые утилиты для директорий данных, дат и ошибок; версии выбирать совместимые с выбранным Rust toolchain.
- Клиент NASA и путь к кэшу должны иметь точки подмены/инъекции для тестов.
- Не выполнять `reqwest`-запросы и синхронные файловые операции в `update()` так, чтобы блокировать GUI.

## Порядок реализации

Сначала создать проверяемый каркас, затем модели/валидацию/парсер, после них сетевой клиент и кэш, и только затем соединить их с UI. Завершить интеграционными проверками и UX-проверкой офлайн-сценариев. Полный пошаговый порядок и результаты каждого этапа записаны в `tasks.md`.
