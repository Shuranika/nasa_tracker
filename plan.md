# План реализации

## Структура модулей

- `src/main.rs` — запуск Tokio и Axum, привязка сервера к loopback-адресу.
- `src/server.rs` — HTTP-маршруты веб-страницы и API, проверка HTTP-входа и преобразование ошибок в JSON-ответы.
- `src/service.rs` — orchestration сетевой загрузки, локального кэша и fallback для выбранной даты.
- `src/nasa.rs` — NASA NeoWs-клиент, десериализация и преобразование ответа API в модель приложения.
- `src/models.rs` — сериализуемая модель астероида и версия формата кэша.
- `src/cache.rs` — системный каталог приложения и атомарное чтение/обновление JSON-кэша по дате.
- `src/date.rs` — разбор и проверка ISO-даты.
- `web/index.html` — автономный адаптивный интерфейс HTML/CSS/JavaScript без внешних CDN.

## Поток данных

1. Браузер отправляет выбранную дату на локальный `GET /api/asteroids?date=...`.
2. Сервер проверяет дату и передаёт сетевую операцию в blocking worker, чтобы не блокировать async runtime.
3. NASA-клиент выполняет HTTP-запрос, десериализует JSON и создаёт модели приложения.
4. При успешном ответе сервис обновляет файловый кэш и возвращает модели вместе с метаданными об источнике данных.
5. При сетевой ошибке сервис пытается прочитать сохранённый результат только для той же даты; ошибки передаются маршрутизатору, а не подменяются пустым успехом.
6. Сервер выдаёт результат в JSON; браузер безопасно строит DOM-карточки, состояние загрузки, ошибок, кэш-fallback и пустого результата.

## Границы и безопасность

- NASA API-ключ читается только Rust-сервером из `NASA_API_KEY`; браузер получает только статус и результаты.
- Axum слушает `127.0.0.1:3000`, не открывая локальный API в сеть.
- Операции с blocking `reqwest` и файловым кэшем выполняются вне async worker.
- Веб-страница встроена при компиляции и не зависит от текущей директории или CDN.
- Сетевой клиент и кэш сохраняют независимые точки подмены для локальных тестов.
