# Задачи для агента-реализатора

Выполняй задачи последовательно, небольшими проверяемыми изменениями и осмысленными коммитами. Сначала прочитай `constitutional.md`, `spec.md` и `plan.md`. Не храни ключи в исходном коде. После каждого этапа запускай относящиеся к нему проверки и сообщай о результате.

## Ветка `implementation`

1. **Каркас приложения** — создай Cargo-проект с `eframe`/`egui`, окном приложения и минимальным UI. Добавь `.gitignore` для Rust-артефактов и локальных секретов, если он отсутствует. Проверь `cargo check`. Коммит: `feat: scaffold eframe asteroid tracker`.
2. **Модели и дата** — добавь модели отображения астероида и парсер даты `YYYY-MM-DD` с реальной календарной проверкой. Добавь модульные тесты валидных дат, високосного года, `31 февраля`, неверного формата и пустого значения. Проверь `cargo test`. Коммит: `feat: add asteroid models and date validation`.
3. **Парсер NeoWs** — опиши необходимые поля ответа serde-моделями и преобразуй их в модель UI; необязательные данные обрабатывай безопасно, невалидную структуру не маскируй. Добавь фикстуру JSON и тесты пустого списка, нескольких объектов и отсутствующих необязательных полей. Коммит: `feat: parse NASA NeoWs feed`.
4. **Сетевой клиент** — реализуй запрос на выбранную дату к NASA NeoWs, чтение `NASA_API_KEY` с безопасным fallback на `DEMO_KEY`, таймаут и явную обработку статусов/ошибок. Сделай HTTP-клиент или endpoint подменяемым для тестов. Не требуй интернета в обычном наборе тестов. Коммит: `feat: fetch asteroid data from NASA`.
5. **JSON-кэш** — определи системный каталог приложения, чтение и запись JSON по дате, сохранение через временный файл с заменой. Различай cache miss, ошибку чтения и ошибку записи; не теряй успешные API-данные из-за сбоя записи. Добавь тесты с временной директорией для чтения, обновления разных дат и повреждённого JSON. Коммит: `feat: cache asteroid feeds locally`.
6. **Соединение UI и сервисов** — добавь поле даты, кнопку загрузки, отзывчивый асинхронный путь, статус загрузки, список с единицами измерения, опасностью и UTC-временем сближения. Добавь fallback на кэш для той же даты при сетевой ошибке и маркируй его в UI; без кэша покажи ошибку. Проверь вручную запуск приложения и не-блокирующее поведение. Коммит: `feat: connect tracker UI to data services`.
7. **Документация запуска** — создай или обнови README: назначение приложения, требования, команды запуска/проверок и настройка `NASA_API_KEY` (не публикуя значение ключа). Проверь актуальность инструкций. Коммит: `docs: document tracker setup and usage`.
8. **Проверки реализации** — запусти `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings` и `cargo test`; устрани ошибки, относящиеся к реализации. Убедись, что `.env`, ключи, целевые артефакты и пользовательский кэш не попали в git.

## Ветка `tests`

9. Создай отдельную ветку `tests` от актуальной интеграционной базы. Добавь недостающие регрессионные и компонентные тесты согласно критериям приёмки: валидация даты, преобразование ответа NASA, ошибки HTTP/таймауты, кэш-fallback только для совпадающей даты, повреждённый кэш и пустой успешный ответ. Используй фикстуры и подмены, не реальную сеть. Коммиты должны отдельно описывать значимые группы проверок; например `test: cover date validation and feed parsing` и `test: cover offline cache fallback`.
10. Запусти весь набор проверок ещё раз и приложи результаты к PR ветки `tests`. Не снижая качество требований, исправь дефекты, обнаруженные тестами, в небольших коммитах.

## Интеграция

11. Открой Pull Request для спецификаций из `specifications` в `main`, затем отдельный PR реализации и отдельный PR тестов; не отправляй изменения напрямую в `main`. В описании PR укажи изменения, проверки и известные ограничения. Если порядок интеграции требует базовой ветки, сначала интегрируй спецификацию и реализацию по PR, а тестовый PR направь в актуальную интеграционную ветку/`main` после обновления.
12. В итоговом отчёте перечисли ветки, PR, коммиты, результаты команд и любые ручные вмешательства, выполненные вне агента Antigravity. Не утверждай, что запуск Antigravity или проверка в GUI выполнены, если они фактически не выполнялись.
