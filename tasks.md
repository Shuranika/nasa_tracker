# Задачи для агента-реализатора

Перед изменениями прочитай `constitutional.md`, `spec.md` и `plan.md`. Не помещай ключ NASA в web-файлы и не коммить секреты. Работай небольшими этапами с осмысленными коммитами и проверками.

## Ветка `web-version`

1. **Rust HTTP-сервер** — запусти Axum/Tokio на `127.0.0.1:3000`; удали запуск desktop GUI. Добавь `/` для веб-страницы и `GET /api/asteroids?date=...` для JSON-результата. Проверяй дату на сервере, возвращай `400` для неверного формата и понятные ошибочные статусы при недоступности NASA. Коммит: `feat: add local Axum web server`.
2. **Сохранение сервисов** — вынеси NASA-запрос, кэш и fallback в слой сервиса. Blocking сетевые и файловые операции не должны блокировать async runtime. Ключ `NASA_API_KEY` остаётся только в серверном процессе; fallback на `DEMO_KEY` сопровождается предупреждением в ответе. Добавь маршрутные тесты для HTML и ошибочной даты. Коммит: `refactor: extract asteroid loading service`.
3. **Веб-интерфейс** — создай автономную адаптивную страницу в `web/index.html` с выбором даты, загрузкой, состояниями ошибки/кэша/пустого списка и карточками с данными астероидов. Создавай DOM без вставки неэкранированных данных пользователя/API через `innerHTML`. Сторонние CDN не используй. Коммит: `feat: build responsive asteroid web UI`.
4. **Документация и тесты** — обнови README, конституцию, спецификацию и архитектурный план под локальное веб-приложение. Покрой API-ответ, HTTP-ошибки, кэш, fallback, невозможные даты и пустые успешные ответы без реальной сети. Проверь `cargo fmt --check`, `cargo clippy --all-targets --all-features -- -D warnings` и `cargo test`. Коммит: `docs: document local web app and run instructions`.

## Запуск и интеграция

5. Проверь в браузере `http://127.0.0.1:3000`; убедись, что ключ не передаётся браузеру, разметка работает на мобильной ширине и карточки не ломаются на длинных значениях.
6. Запускай сервер с установленной в том же окружении переменной `NASA_API_KEY`; не публикуй значение переменной в терминальном отчёте.
7. Публикуй изменения отдельной веткой и интегрируй их через Pull Request, не прямым push в `main`. В отчёте отдельно укажи, если проверка GUI-браузера или создание PR не были выполнены.
